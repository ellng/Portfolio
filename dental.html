Overview

Large pop-up dental clinics run dozens of chairs at once, and every chair needs enough suction to clear fluids and aerosols. All of that suction comes from a few central pumps through a temporary piping network. If the pipes are too small or the runs too long, the chairs at the far end lose vacuum.

This project is a MATLAB and Python simulation for designing and optimizing that vacuum piping network. It simulates different clinic layouts, computes the suction and flow rate at every chair, and recommends the best pipe sizes for each part of the clinic. The baseline model is the 68-chair community clinic the CT Foundation for Dental Outreach runs in Mansfield, CT. I led development of the web GUI, a configuration wizard that lets the clinic team build a layout and run the optimizer without touching the code.

Physical model

The clinic is a branching vacuum network. The pumps pull air through a trunk line, which feeds a main distribution line, which branches through tees into rows of chairs. Each chair is a flow sink with a fixed demand and a minimum vacuum. The model tracks pressure from the pumps to every chair, adding up losses along the way.

Friction and fittings

Each pipe segment combines Darcy-Weisbach friction with minor losses from elbows and tees. The friction factor is 64/Re for laminar flow and the Blasius correlation for turbulent flow.

h = (f·L/D + ΣK) · V² / 2g

Compressibility

Under vacuum, the air is less dense, so the same mass flow takes up more volume and moves faster. The model scales the local flow, density and viscosity with absolute pressure.

Qlocal = Qfree · Patm / Pabs

Pump curve

Vacuum pumps deliver less vacuum as flow demand rises. Without a published curve for the V15M, the model assumes a parabolic one, with demand split evenly across pumps.

Pvac = Prated · (1 − (Q/Qmax)²)

Diameter changes

An extended Bernoulli equation adds a kinetic-energy correction wherever the pipe steps down in size, since velocity changes sharply there. α = 2 for laminar flow and 1 for turbulent flow.

p₁ = p₂ + ρ(½α₁V₁² − ½α₂V₂²) − ρg·h

Pressure cascade

  1. Pump. Total clinic demand is split across the pumps, and the pump curve sets the available vacuum at that load.
  2. Trunk. Flow passes through the trunk segments, adding friction and fitting losses.
  3. Main line. At each row, a branch tee diverts that row's flow and the rest continues through a through-tee.
  4. Rows. Flow feeds pairs of chairs along each row while the pipe steps down in diameter by zone.
  5. Chairs. Each chair's vacuum is the pump vacuum minus all losses upstream. It passes if that's above its minimum.

Pipe-size optimization

The optimizer runs a brute-force search over discrete pipe sizes: 2, 3 or 4 inches for the trunk, and 1.5, 2 or 3 inches for the main line and each of four row zones. That's 2,187 combinations before filtering. Diameters must shrink or stay the same moving away from the pumps, and any design where the air reaches Mach 0.3 or leaves the Blasius range is rejected outright.

ObjectiveWhat it optimizes
A · DeficitFewest failing chairs, then smallest vacuum shortfall, then least material
B · Pass rateHighest fraction of chairs meeting the vacuum target
C · VelocityFewest failing chairs, then a penalty for air speeds outside 3,200–5,000 fpm: slow enough lets debris settle, too fast adds noise and wear
D · RobustBest worst case across 12 scenarios: four usage factors (30–60%) with four, three or two pumps running

The robust objective also detects scenarios no pipe size could fix. With only two pumps at 45% usage or higher, the pumps themselves supply less than the 11 inHg target. Rather than letting those cases skew the ranking, the optimizer reports them as pump-limited and excludes them from selection.

Model limits

Vacuum is evaluated where each chair branches off its row line. Chair drops, hoses, valves and handpieces aren't modeled yet, so a passing connection doesn't guarantee enough suction at the handpiece. The model also assumes smooth pipe, all piping at one elevation, and a pump curve estimated without manufacturer data. These are the next things to measure and add.

Code and GUI: the MATLAB and Python solvers and the web GUI are in the process of becoming open source. Links to the repository and a hosted version of the GUI will be added here once they're public.
